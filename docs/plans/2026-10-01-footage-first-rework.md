## 1. 现状：看过摘要，仍然先写文字结构

**故事与旁白究竟何时写？** 故事不是完全没看素材：P1 前已读库存摘要，但还没看逐片画面、没有可引用片段。摘要最多 3,500 字符：48 个高频主体/动作/产品/叙事功能词、24 个场景词、16 个 OCR 样例及数量；不含片段 ID、源区间、逐片说明、底线风险或镜头关系。P1 还明确禁止选素材 ID。开配音时，Agent 写的稿甚至早于领域内这次盘点，并已在 P1 前合成；关配音时 P1 不写旁白。Agent 可另查库概览或单素材详情，但概览只是频次与少量 caption/narrativeRole 样例，详情工具也未输出 detail，不构成策划引用契约。

**四类问题分别落在哪：**

- **先编故事再硬凑**：P1 仍以 brief 意图为先，允许缺画面时改成“最接近的证据类型”，且没有片段引用。后续召回只能服务已经写定的要求，P4 又不能改选片身份。
- **文字画面对不上**：`select_one_beat` 在无直证、低匹配时允许 `contextual`（仅承载情景）；`collect_phase3_issues/validate_storyboard` 验证 ID、源窗、拍顺序和复用，不独立证明画面支持卖点。合法引用不等于语义真实。
- **别家品牌/展会入选**：`compact_candidate_card` 把 brandLogos/exhibition/focus 交模型参考；`calculate_candidate_score` 只有软质量分，没有这些淘汰门，P5 也不检查。代码现有硬过滤主要是可访问性、用户排除、范围和重复；昼夜规则候选少时还会撤销过滤。
- **反问/说错结果**：反问不全是模型任性：`generate_storyboard_internal` 的缺稿、口播时长冲突、无可选画面均返回需用户决定，`agentloop/skills.rs::safe_tool_failure_context` 要求提问。`native.rs::finish_native_result` 以执行回执判终态，但 `native_result_from_message` 仍直接用模型文本覆盖产物消息；不能据此保证所有自然语言事实一致。

**已识别字段实际用了多少：**

| `VisualEvidence.detail` 字段 | 当前使用与缺口 |
|---|---|
| changes、highlights、concepts、mood | 经 `models.rs::VisualEvidence::detail_phrases` 进入 `semantic.rs::evidence_text/segment_evidence_text` 与 `scoring.rs::evidence_blob`；也给 P3。描述被召回，但没有据变化建立动作/因果关系 |
| bestRange、highlights 的时间 | 给 P3；`length.rs::evidence_anchor_ms` 已用于定长裁切锚点；尚不等于独立验证“最佳源区间” |
| timeOfDay | 给 P3，且 `daypart.rs::sources_for_rule` 有可撤销的昼夜过滤 |
| focus、onScreenText、textLanguages、brandLogos、crowd、exhibition、verticalCropFit | 只给 P3 标签参考；未进体裁硬过滤/可用性评分，也不保证随画幅变化 |
| cleanStart、cleanEnd、edgeNote、subjectDirection、cameraDirection | 给 P3；未形成切点或镜头关系硬规则 |
| setting、colorTone、brightness、peopleCount、facesVisible、safetyGear | 给 P3；未形成独立排序或校验规则 |

不能把“未硬使用”写成“完全没用”。另有缺证据：抖动程度、背景杂乱、摆拍/广告感、人物一致性、动作前后状态和轴线；运动能量不是抖动检测，subjectDirection 也不能单独证明跳轴。

## 2. 目标：先证明能剪什么，再决定讲什么

保留 Agent 处理对话与编辑意图；一次生成工具内部由 Rust 执行固定顺序。模型只完成有输入输出契约的理解、提案与判断，不能修改流程、结构预算或绕过校验。

| 新步骤 / 决定者 | 输入 → 输出 |
|---|---|
| ① 素材盘点：代码定范围，AI 理解 | 用户需求 + 本轮媒体快照 + 已分析片段 → 逐片证据清单与“可讲内容/缺口”。每项带 assetId、segmentId、源窗、分析版本；保留模型自由描述和临时人物/事件关联，不建场景/功能类目。分批覆盖全库，不用高频词代替低频关键片段 |
| ② 体裁：模型判自动，代码守用户选择 | 需求 + 盘点 → 叙事/宣传/花絮与理由；手选不可被改。自动信息不足用暂定默认宣传并说明，不反问；只判断一次，保存快照。自动叙事缺因果证据可判花絮，手选叙事缺证据则明确受限 |
| ③ 底线与可用性：代码裁决 | 证据 + 体裁 + 画幅 + 本项目品牌身份 → 合格/淘汰/待核验清单、原因与可用窗。未知不当作合格；只补核验影响本次成片的候选。硬淘汰无权被“匹配度高”救回 |
| ④ 体裁配方：代码 | 合格片段 + 时长意图 → 结构段、段数、时间预算与关系约束。结构段内部再分镜，避免“卖点段=一镜”；段数与预算不由写稿模型决定 |
| ⑤ 有引用的策划：模型提案，代码验收 | 配方 + 合格证据 → 每段可讲内容、引用片段、所支持的具体表达与备选。引用必须在允许集合且源窗合法；宣传卖点须有直证，气氛镜仅用于钩子/过渡。产能等数字不能从设备画面推断，只用用户给定且注明来源的事实 |
| ⑥ 选镜与镜头关系：模型看图打分，代码全局组合 | 策划引用 + 同段备选 → 候选适配评分与关系证据；代码分配镜头、去重复、定顺序。与冻结镜头冲突也淘汰；不能各拍独立选完只处理 ID 撞车 |
| ⑦ 源窗与节奏：模型判断高光，代码定时钟 | 选中窗 + 动作变化/最佳区间/主体边界 + 配音/音乐时钟 → 精修源窗、槽位、裁切及切点；窗不可跨硬切，身份不可改，不能为凑时间把淘汰画面补回来 |
| ⑧ 校验与落地：代码 | 全部证据、计划和镜头 → 引用、底线、关系、重复、时长、画幅、声音检查；通过后写新故事版和时间线，生成预览、新编辑器交付、备选清单与事实回执。失败不提交半成品为“完成” |

**体裁配方暂行数值**（是可版本化代码参数，不是提示词；缺素材时收缩内容，不能编造补齐）：

| 体裁 | 结构与段数 / 默认预算 | 淘汰与镜头关系 / 节奏 |
|---|---|---|
| 叙事 | 开端→发展→转折→结尾，4 段，20/35/25/20%；暂定 30 秒 | 已证实因果/动作状态矛盾、跳轴、无关插入硬拒；代码按人物/事件关联与动作前后依赖排序。缺转折不制造转折，输出缺口；情绪可长镜，轻微瑕疵不自动淘汰 |
| 宣传 | 钩子→2–4 卖点→品牌/行动，4–6 段，15/70/15%，卖点预算按支持强度分；暂定 30 秒 | 主体失焦、不可接受抖动、非本项目品牌、展会/展台/展厅、杂乱背景硬拒。卖点内只允许同一论据的镜头互换，代码安排规模/细节变化；通常每镜 1.5–3.5 秒，内容可读后才卡拍 |
| 花絮 | 开头→1–3 组真实瞬间→收束，3–5 段，10/80/10%；暂定 20 秒 | 已证实摆拍/广告感硬拒；空镜比例暂定 ≤20%，超过则组合无效，不是把每条空镜全删。按有证据的时间顺序或本次 AI 归纳的主题关联组合；无时间证据不声称按真实日期排序，手持/轻微失焦可接受 |

每段时间由代码在预算与可用窗内分配，用户秒数优先；段内镜头数由预算和最短可读时长计算。过短请求使用配方的短版，合并非必要过渡，不机械塞满所有段。上述默认、阈值由评测校准，冻结配方版本后再对比。

**底线和评分不能混用。** AI 提供风险事实、位置/区间及不确定性，Rust 执行规则。宣传本项目品牌按项目品牌套件/用户给定身份匹配；未知标识先核验，无身份时暂排除所有带标识候选，不从文件名猜品牌。全段 exhibition 等无时间范围的标记先按整段排除，不能靠随意裁切“去掉风险”。补分析增加风险时段、稳定性、背景干扰、人物/动作关系等证据，不增加素材分类。旧字段无置信度时视为未核验；正向命中直接淘汰，关键未知需再看图才可放行。

可用性分用于合格集合内比较：技术可读、主体可见/可裁、动作完整与高光、源窗容量；匹配分用于某段内容是否有直证；序列分用于关系、重复、景别变化。各项保留分项，不允许高匹配抵消硬风险。叙事关系中的跳轴须有机位/轴线证据，方向反转只是待核验信号。底线既在入池执行，也在最终源窗和局部重选后执行。

**保留 / 改造 / 退出：** 保留硬切、运动窗、关键帧网格、本地文本/CLIP 召回、P4 锁窗与局部重试、版本化时间线、预览及交付。改造库存摘要为引用清单；P1 为“配方内有证据的策划”；P2/P3 加入底线与全局关系组合；P5 加语义支持和体裁门；局部重选共用同一策略与冻结约束。删除新链路中“纯文字先定故事”“卖点用情景镜凑”“候选少便撤销底线”“模型自行定段数/时长”的分支；精修类已有能力留存、不扩建。失效旧函数在兼容适配后移除，不重写历史产物。

## 3. 评测：先冻结基线，再重做

**第一任务交付可重跑的基线，不是分数猜测。** 后续执行会话在隔离工作目录、独立应用数据目录中：冻结 94 条原片清单/内容哈希、分析与向量快照、源窗、固定需求、媒体开关、Provider/模型、代码与配方版本、项目使用次数。每个用例从同一空产物状态起跑，关闭跨用例新鲜度污染；分别测“冻结已有分析”和“重新导入分析”，不混算。当前有未提交 Cargo 改动，基线须保存其版本标识或明确使用干净提交，不能只记 HEAD。

需求先恢复 09-27 三次原文与开关；再固定中英文宣传、15/30 秒、自动/手选、开关配音/BGM、缺画面、局部换镜等约 10 个用例，每例跑 3 次，报告均值与最差值。记录阶段输入输出、候选及淘汰原因、计划、时间线、音频时钟、产物路径和执行回执。沿用已有 `storyboard/provider_trace.rs` 的阶段轨迹思路；增加可独立输出到评测目录的运行器。另可回放保存的模型响应验证规则稳定，但回放不能代替真实模型质量评测。

| 自动指标 | 分母/判定与建议门槛 |
|---|---|
| 硬淘汰入选数 | 按人工金标核对最终源窗，分体裁统计；每次为 0，同时测识别漏检率与误杀率，防止“代码过滤了已知标签”被当成识别完成 |
| 策划引用真实性 | 每段至少一个合法引用、允许范围内且可访问；段覆盖率 100%、非法 ID/越界为 0；另报语义直证覆盖率，宣传卖点 100% |
| 素材复用与相似复用 | 分别报重复 assetId、重叠源窗、相似画面；能在同样语义/关系约束下组成全不复用序列时，重复 assetId 为 0，否则写可用性不足证明，不能只用全库数量判断“够用” |
| 时长与时钟 | 对用户目标和实际主时钟分别报毫秒/百分比偏差；精确时长模式建议 ≤max(1 帧, 2%)，源区间不越窗；音乐乐句模式沿用 ≤25% 目标偏差但须明示实际长度 |
| 体裁与关系 | 自动判定混淆矩阵，暂定正确率 ≥90%；手选遵守率 100%；金标确认的矛盾/跳轴为 0，花絮空镜比例 ≤20% |
| 一轮与事实 | 无必要提问次数为 0；产物状态、版本、配音/BGM/卡点/交付失败等固定事实与回执不一致数为 0；失败用例不得宣称完成 |
| 最佳区间与覆盖 | 人工标注可接受高光区间，自动查重叠、动作截断及风险时段；对未标注样本只能报约束通过，不能叫“最好”。防止空结果投机：有足够合格素材的用例必须产出且覆盖计划 |

用户只需：指出本项目/别家品牌；找回原始三次需求和结果（找不到则标“新基线，非历史复现”）；对工业片段核对禁用原因/时段，标少量卖点支持关系、可接受最佳区间，并确认哪些素材足够出片。执行会话先机器预标、用户纠正即可；不要求人工建场景类目。按片段/事件划分校准与保留验收样本，避免拿同一标注反复调参后宣称泛化。

**只有工业素材怎么办？** 先把宣传基线和负面用例做扎实；同一工业库可测体裁切换遵守、缺因果链诚实失败和花絮规则，不能据此证明三体裁可用。用户补两套小素材：同一事件含起因—过程—变化—结果的 12–20 条叙事片，以及自然互动/幕后瞬间的 15–25 条花絮片。可用现有手机原片；经授权的公开素材可先作开发验证，必须有真实事件关系且保留许可。上线仍需三体裁各一套真实出片、用户看过认为可用，不以合成数据或片段复刻抵账。

## 5. 风险与取舍：历史可读，新增产物才受新规则

- **项目/版本**：新故事版追加 pipelineVersion、genre、recipeVersion、证据快照与引用，缺字段走旧读取适配；不回填、不重编号、不重新分析所有共享素材。旧故事版能预览/交付，但不贴新选镜合格标签；在旧版局部改片时，未改画面冻结并报告历史风险，派生版也不能冒充全片达标。
- **识别与性能**：旧库缺稳定性、关系与风险时段，先复用分析、仅核验候选和关键未知。保留 ≤4 张图/请求和限流退避；独立理解/评估可并发，全局关系分配由代码串行裁决。模型误识别仍需金标衡量，不能承诺“代码能证明画面内容”。
- **配音**：新生成的文案应在有引用策划通过后才写/合成；用户自带可念稿照念，但先查画面覆盖，缺证据不强配。已存在旁白仍冻结，局部改片不重合成。实际 TTS alignment（词句时间戳）继续是时钟；自动写稿只允许合成前缩稿，合成后禁止改字。
- **BGM/源窗**：保留配音优先、无配音时音乐窗口、否则内容定长的优先级及 ±120ms 配音卡点容差；体裁配方给初始预算，最终以选定主时钟重分配。宣传不为口播拉出极慢镜头，先在策划阶段降低信息量或挑足够长的合格窗；已有固定稿冲突须明示，不能偷偷截稿/冻帧/跨硬切。
- **交付**：保留内部时间线与 HandoffPlan（把时间线翻译给编辑器的统一交付计划）为唯一来源；备选用本地清单随新交付物带出，不假定所有编辑器支持原生“备选槽”。变速、裁切、声音偏移须实际导入验证，尤其 TASKS 已记的 FCPXML timeMap 风险。已有品牌卡/转场保留，新增体裁流程不继续扩大精修范围。

## 6. 需要用户拍板（其余按上述建议推进）

1. **无稿但开配音**：是否以“有证据策划后自动写稿并直接出粗剪”替代现行先问同意？建议默认自动，用户给原稿才锁原文；未批准前保留现有确认门，不能声称完整一轮。
2. **体裁标准与异常规则**：是否接受暂行预算/默认时长；宣传展厅是否与展会一并禁用；花絮空镜 ≤20%；叙事资料不齐是否仅交缺口。这些是参数与边界的确认，不重新讨论已定三体裁/默认自动。
3. **品牌与证据不足的默认**：确认本项目允许品牌；是否接受未知标识先排除、目标时长缺合格素材时出较短且标明受限的粗剪。建议绝不放宽硬淘汰；无合格镜头明确失败。
4. **时长与声音取舍**：明确秒数时建议默认精确模式，音乐乐句优先另行选择；用户原稿覆盖不足、时长冲突保留必要确认。花絮建议保现场原声、音乐轻，是否允许用户开关以外的自动音量调整。
5. **验收投入**：确认可提供两套小型真实叙事/花絮素材，并接受预标后纠正的金标流程及暂定自动判定 ≥90% 门槛；“最佳区间”和三体裁可用仍由用户看片确认。
