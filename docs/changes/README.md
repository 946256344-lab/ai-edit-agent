# 架构变更记录

每次触发 `.harness/doc-sync-policy.json` 的架构级源码改动，都必须在同一变更集新增或修改一份本目录中的记录。文件名使用 `YYYY-MM-DD-主题.md`。

记录必须包含：

- 触发范围：实际改动的源码路径和对应规则。
- 改动：架构、公开契约、持久化或产品边界发生了什么变化。
- 同步文档：本次变更中修改的 `AGENTS.md`、`README.md`、`TASKS.md` 和 `docs/*.md` 路径。
- 验证：运行的 harness、测试、构建或人工验收结果。
- 决策：是否新增或更新 ADR；没有决策变化时明确写“无”。

`npm run harness:check` 会检查触发规则所要求的文档是否出现在变更集，并确认至少一份记录列出了它们。该检查不能判断自然语言是否真实反映实现，因此 Agent 还必须执行 `docs/harness.md` 中的独立审查 loop。
