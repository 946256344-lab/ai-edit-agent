# 画面分析队列多任务同时执行

## 现象

导入或重新识别后，画面分析队列一次只执行 1 个任务（最多 6 段），做完才领下一个。素材多时识别时间随任务数线性增长，Token Plan 的请求额度大部分闲置。

## 根因

`spawn_visual_analysis_worker` 用一个全局开关保证只有一个工作线程，循环里每次领 1 个任务。

## 触发范围

- `src-tauri/src/assets/visual.rs`：队列改为最多 `VISUAL_ANALYSIS_RUNNERS = 16` 个执行线程，每个线程循环领取任务。领取在进程内串行，按优先级取第一个素材未被占用的排队任务，数据库侧仍以 `status = 'queued'` 条件更新防止重复领取；同一素材的任务不同时执行，避免两份结果同时改写同一素材元数据而冲突。线程做完释放素材占用；没有可领任务时，若还有其他线程在执行就直接退出，由它们接着领取；最后一个线程负责补跑可重试失败和兜底重启。
- 任务内按素材分组、各组并发（每请求一条素材、最多 4 张图）保持不变。视觉请求仍让位于生成与对话请求，熔断与 429 退避不变。

## 改动

公开命令与 schema 不变。16 只限制本机同时执行的任务数，请求本身不限速。
