# 剪辑失败与重复耗时修复

分支：`codex/fix-editing-failures`，基线：`992db00`。

## 问题与改动

2026-09-10 10:54–11:57 的同一 Agent 任务连续执行四次 `generate_storyboard`，全部返回 `storyboard_selection_failed`。最后一轮 18 镜全部为 `outside_candidate_segment`，没有保存分镜或时间线。整素材候选会展示 sceneSegments，但旧模型返回的 segmentId 只有在候选已展开为片段时才被校验接受。

- Phase 3 统一只返回每个 beat 的 `candidateIndexes`，Rust 从实际候选取素材 ID、片段 ID 和时间范围；初始提示及修正提示保持一致，同一 beat 仍要求不同素材。
- Phase 4 的来源按素材去重，避免同素材多个片段导致来源数量检查失败；镜头仍保留具体片段约束。
- 片段视觉批次纳入启动恢复，running 恢复到 queued，已有素材视觉状态和片段证据保留。
- Phase 3/4 继续使用原有局部修正预算；耗尽后返回不可重试结果，Native 同轮缓存失败结果，模型再次请求也不重新执行整套分镜。
- Native 的同步模型、配音 HTTP、媒体子进程与素材等待共享总剩余预算；在阶段边界及分镜落库前检查。后台队列不继承用户本轮预算。ONNX 和系统文件操作不能强制中断，推理前后检查及子进程清理可能有有限延后。
- 修复进程管道堵塞：FFmpeg/FFprobe 运行时同时读取 stdout/stderr，避免先等待退出导致大输出填满管道。原有进程树超时回收保留。
- 视觉请求失败记录现有安全 Provider 错误码，返回内容无法解析使用 `visual_response_invalid`，不再把这两类失败混为 `visual_request_failed`。
- 素材级与片段级视觉响应兼容 Provider 偶发的字符串/字符串数组及单值/时间范围差异；提示继续要求稳定类型。解析失败日志只记录长度和解析错误，不写模型响应正文。

公开 Tauri 命令、数据库 schema、前端界面及用户项目内容均未改变。没有增加自动重试、切换 Provider 或放宽选镜校验。

同步文档：`docs/api.md`、`docs/architecture.md`、`TASKS.md`。
