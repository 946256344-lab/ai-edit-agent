# 交互 Agent 首次决策与 Provider 优先级

## 问题

一段英文创作文案在待补充项目目标的会话中，被独立分类模型当成问答；主循环又先观察素材再回答，叠加慢 Provider 和后台粗视觉请求后耗时约四分钟，最终只返回翻译。

## 变更

- 移除模糊请求的独立模型分类往返；首次主模型响应同时声明目标并选择首个技能或直接回答。
- 保留确定性快路径和真实产物完成门；无效目标声明在任何工具副作用前失败封闭。
- 读取最近同作用域 `needs_clarification` 作为结构化上下文，使用户补充文案能结合上一轮问题理解。
- Agent 模型决策使用 90 秒协作式总预算；每次请求使用剩余预算，不强杀已经开始的副作用。
- Provider 请求边界优先交互模型调用；粗视觉连续三次失败后熔断 60 秒，任务保持 queued，并由单一半开探测恢复。
- `agent_diagnostics` 只记录固定数字耗时和安全错误码。
- 同步过期的 Agent 工具 fixture：当前为 18 个技能、10 步，并记录 `goal`/`isQuestion` 元字段。
- 将“剪好了吗/完成了吗”等精确状态问题改为只读 `get_edit_status` 直通，不再调用模型。

## 安全边界

- 不记录模型响应原文、用户文案、媒体证据、路径或凭据。
- 模型声明的完成事实不能替代真实 storyboard、timeline、preview 或 Jianying draft。
- 熔断不自动重放未知副作用；只延后尚未开始的粗视觉请求。

## 验证

- `cargo test`：82 个库测试和 2 个契约测试通过。
- 真实桌面 Provider 延迟、熔断恢复和英文文案首轮行为仍需手工验证。
