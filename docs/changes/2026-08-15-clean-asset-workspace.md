# 2026-08-15 最小素材工作区重建

## 目标与边界

在已恢复的后端安全目录投影上重建素材前端，不继续修补传统素材管理器。保留导入、目录浏览、整体分析摘要、源文件异常恢复和派生证据；不删除任何素材、用户元数据、分析结果、后端命令或 Agent 工具，不重新分析媒体，不修改 storyboard、timeline、preview 或 Jianying draft。

## 删除的前端层

- 搜索，以及类型、技术状态、视觉状态、用户状态和集合筛选。
- 批量选择、收藏、评分、备注、标签、集合、禁止使用、技术重试和视觉跳过入口。
- 素材任务中心、最近失败定位和与这些功能对应的顶层 React 状态、轮询及 CSS。
- 重复的文件夹下拉框、子目录快捷条和页面外悬浮重链路按钮。

后端的分页、检索、用户元数据、批量操作、任务摘要、审计与 Agent 能力全部保留，避免 UI 重建演变成数据破坏或契约收缩。

## 干净边界

- `AssetManagementPanel` 从约 500 行、50 个扁平 props 收敛为约 116 行，只接收 `model` 与 `actions` 两个领域入口。
- 目录、素材列表、证据和源恢复拆为独立组件；`App.tsx` 的素材相关 state 从约 20 个缩为 8 个必要状态。
- `AssetDirectoryTree` 局部持有 `expandedFolderIds`，`toggleAssetFolder` 是唯一开合动作。根目录首次从后端出现时自动展开，子目录默认折叠；只有展开节点渲染子树，`aria-expanded` 与视觉状态一致。
- 目录切换仍先清空旧素材，再加载后端 `directoryKey` 对应的直属页；旧请求在 effect cleanup 后不得回写。
- 重链路保持两阶段预览/确认，并固定保留现有分析证据；界面不显示用户选择的绝对根路径。
