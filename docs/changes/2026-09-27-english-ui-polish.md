# 英文界面与状态显示修正

## 现象

录宣传片时发现（英文界面）：

- 素材库 4 列布局下，素材卡状态「Analyzed」被截成「Anal」。
- 新建项目选子素材库时，默认子库仍显示中文「未归类素材」。
- `generate_storyboard` 成功（分镜、时间线、预览、CapCut 草稿都已生成），任务卡却显示「Partially completed」。
- 空对话引导语写死「交给剪映精修」，输出编辑器选 CapCut 时也这么说。
- 旧项目「1111」同一会话有 6 条相同的「Imported 94 items from the folder…」。

## 原因

- 卡片底部一行放「状态 + Rename + View analysis ↗」三项，卡宽约 170px 时两个英文按钮已占满，状态被挤到只剩几个字符。
- 默认子库名是 Rust 写入的存储数据，前端直接显示。
- 「Weekend Road Trip」两轮任务中，模型各有一次 `search_assets` 传错参数（`invalid_arguments`）且没有再调；回执里失败工具集合非空、另有成功工具，就判为部分完成。交付物其实一件不缺。
- 引导语文案里写死了剪映。
- 本地库核对：6 条提示各对应一次真实文件夹导入，每次导入前约 10 秒刚把上一批 94 条从素材库移除（重新识别测速时的操作）。每次导入都会追加一条同样的提示，互相之间没有别的消息。

## 改动

- 素材卡：状态移到路径行右侧，不收缩、完整显示并带悬停提示，窄卡时只截断路径；Rename / View analysis 单独靠右一行，放不下时换行。2 / 3 / 4 列（卡宽 190px 起）英文最长状态「Analysis cancelled」也能完整显示。删去已隐藏不用的时长文案键。
- `list_shared_libraries` 增加 `unfiled`（源目录为空的默认子库），前端对它显示 `assets.unfiled` 译文；存储名不改。
- 只读查询本机项目事实的工具失败、本轮另有成功工具时，整轮不再判为部分完成；`search_music`、`list_voices`、`transcribe_asset` 与写工具失败照旧计入。任务卡折叠行在已完成步数后另列「N 步失败」，展开可见具体步骤；质量提醒仍由 Agent 回复说明，不受影响。
- 引导语按当前输出编辑器名称（剪映 / CapCut / FCPXML / OTIO）显示。
- `create_message`：`role=agent` 且会话最后一条就是内容相同的 agent 消息时不再插入、返回原消息，前端不重复追加。中间有其他消息时照常追加。

## 已知限制

- 已存储的部分完成任务与重复提示不回溯修改。
- 手机宽度（卡宽 150px）下最长状态会把路径挤到几乎不可见。
- 未移除时再次导入同一文件夹仍会新建重复素材（本次记录的情况是先移除再导入，不涉及），另记待办。
