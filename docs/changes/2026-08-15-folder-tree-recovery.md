# 2026-08-15 素材文件树恢复

## 目标与边界

先恢复用户按文件夹导入时的本地相对文件树，再单独决定哪些素材管理前端控件删除。本次不删除或重新导入素材，不启动重新分析，不修改 storyboard、timeline、preview 或 Jianying draft。

## 真实基线与根因

- 当前项目共有 891 条素材；SQLite 中每条仍有源引用和 `folder_reference`，但旧 `folder_reference` 全部指向没有可展示 `file_name` 的 UNC share 根。
- 旧安全投影要求根路径具有可展示的文件夹名，因此该 UNC share 根使 `asset_safe_directory` 对 891 条全部返回空，桌面 API 报告 `directories=0`、`unfiledCount=891`。
- 后端已有面向早期无根记录的共同父目录恢复算法，但只在 `folder_reference IS NULL` 时使用，没有覆盖“字段存在但不可形成安全目录”的记录。
- 后端目录筛选使用完整安全目录键，前端却再次把 item 的根 `folderName` 与完整目录键比较，导致子目录列表被过滤为空。
- 目录节点计数由当前最多 100 条素材推导，且轮询会把已不匹配的旧卡片继续合并，出现匹配总数为 0 但仍显示旧卡片的矛盾状态。

## 实现

- `StoredAsset` 增加安全 `directoryKey`；`AssetPage` 以 `directories: { key, name, parentKey, directAssetCount }[]` 和 `unfiledCount` 返回完整项目的权威目录投影。
- `list_asset_page` 的目录参数改为 `directoryKey`，仍只返回该目录的直属素材；目录节点和计数不受当前分页或其他筛选影响。
- 根引用能严格解析时沿用保存的导入根；根引用为空、没有可展示名称的盘符/UNC share 根或无法严格包含源引用时，把这些旧记录交给安全卷分组算法。算法只依据路径结构和至少两条同卷记录，不读取媒体内容、不按文件名猜测。
- 公开的 `folderName`、`relativePath` 和 `directoryKey` 从安全投影生成，不包含盘符或绝对路径。
- React 素材组件仅用后端目录节点建立父子关系；`App.tsx` 不再从当前页重建树或执行目录二次过滤。每次轮询以后端当前页替换素材列表，避免旧筛选结果残留。

## 已知边界

- SQLite 及 schema version 不变；这是读取时的加性投影。
- 空文件夹、只含不支持媒体的文件夹无法从素材记录恢复。
- 只有一条且没有可用根引用的旧素材不能可靠推断导入根，继续归入“未归类素材”。
- 旧数据回退先剥离并按普通/扩展盘符或 UNC server/share 隔离；单个安全卷没有可公开共同父目录时使用固定“导入素材”根，多个可恢复卷组统一加独立“导入素材 N”命名空间，防止同名相对树碰撞。无法安全解析的记录只让自身留在未归类；服务器、共享名和盘符片段都不会进入目录键。
- 收藏、评分、标签、集合、批量操作、任务中心等控件本次保持不变，等待文件树稳定后再做独立删减决策。

## 验证

- 128 个 Rust 单元测试和 2 个契约测试通过；定向覆盖正常文件夹根、盘符/UNC 根回退、固定安全根、多卷同名树隔离、跨 server/盘符隔离、不安全记录隔离、祖先节点和直属素材计数。
- Rust fmt、前端 lint/build、文档同步 harness、差异检查和独立契约审查通过。
- 真实 Tauri WebView 返回 891 条素材、13 个安全目录节点、`unfiledCount=0`；界面显示 1 个导入根、10 个一级和 2 个二级目录，最大深度 2。
- 进入一个有 72 条直属素材的子目录后，后端与界面均为 72 条，每条 `directoryKey` 都等于所选目录。
- 进入一个只有子目录、没有直属素材的父目录后，后端和界面均为 0 条素材，同时仍显示 4 个直属子文件夹；没有陈旧卡片。
- 检查确认公开目录键和相对路径不含盘符。整个桌面验收未点击导入、分析、健康扫描、重链路或批量操作。
