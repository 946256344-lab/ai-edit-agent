# 当前决策

本文只记录今天仍然有效的产品与技术决定，按主题排列。被取代的决定直接删除或改写，历史查 git 与 `docs/changes/`。协作流程见 `CONTRIBUTING.md`，系统现状见 `docs/architecture.md`，首发事项见 `docs/release-checklist.md`。

## 一、产品方向

### 产品核心是策划与选镜（2026-09-27，最高优先）

Voycut 的价值只在两件事：**策划**（这条片讲什么、分几段、每段要什么画面、多长、什么节奏）和**选镜**（从用户素材里找出每段最好的镜头和区间）。成品精修（花字、动效、片尾卡、转场、调色）交给剪映 / CapCut / Resolve 等编辑器，不在应用里做成品。背景：09-27 用 94 条工业素材连测三次宣传片，问题都出在「先按文字编故事再到库里硬凑画面」和「模型临场决定怎么剪」，精修层补得再多也救不回来。

- **素材先行**：先看懂素材、挑出可用的好镜头，再据此定策划；不先按文字需求编故事再去库里硬凑。库里没有的画面，策划里不写。
- **模型是零件，不是导演**：模型负责看懂素材、提出策划和文案、判断镜头好坏；结构、时长、节奏、顺序规则和校验由代码决定。不靠往提示词里加规则来修产品问题。
- **一轮出结果**：能用默认值定的事不反问用户，缺的信息用默认值补上并如实说明。
- **新功能先过一道问题**：它是否让策划或选镜更好？不是就不做。已有的精修类能力（品牌卡、花字模板、转场、对话改片工具）保留现状，不再投入。
- **先分剪辑体裁：叙事、宣传、花絮**。体裁决定策划结构和「什么是好镜头」（同一条手持晃动的镜头，宣传要淘汰，花絮可能最好），所以策划和选镜都先按体裁走。体裁的确定方式（09-29 用户定）：输入框里给「自动 / 叙事 / 宣传 / 花絮」选项，默认「自动」，由 AI 从需求和素材判断，并在结果里说明用了哪种；用户选了就按用户的。三种体裁各自的标准待用户给出后补在这里。
- **不给素材做人为分类**：不建场景 / 功能等类目体系让素材归类，素材理解由 AI 直接完成；人定的类目会把 AI 的理解降成打标签。

### 首发：10-01 小范围免费内测（2026-09-28，用户定）

- 10-01 海外小范围免费内测，不收费。收费等「策划 + 选镜」重做后成片过关、有单次成本实测再定。内测期间主力投在产品核心重做，官网只做发布必需的部分：下载、已知限制、Terms / Privacy、删除渠道、账号。
- 不设邀请名单，只私下发下载链接。使用资格整个内测期有效，不按 7 天过期。不设每人额度（09-29 用户定）：用户用到开发者的上游套餐（Agnes Token Plan）限额为止，上游限流时如实提示；出事时用网关总开关停用。已知风险：链接被转发时，个别重度用户可能耗尽套餐、让所有内测用户一起受限，用户接受。网关保留按人计数的能力，但默认关闭。

## 二、基本原则

- **本地优先**：项目数据、原始媒体引用、分析结果、storyboard、内部 timeline 和 preview 默认保存在本机。导入不修改原始媒体。
- **Rust 负责本地副作用**：React 通过 Tauri 命令表达意图，Rust 负责 SQLite、文件、媒体工具、模型请求和产物创建。前端不直接访问数据库或本地文件。
- **Agent 使用工具完成剪辑**：自然语言请求进入 Agent 工具循环，模型可以观察项目状态、选择素材、生成 storyboard、编辑 timeline 和请求 preview；模型文字本身不能证明产物存在。
- **Storyboard 先于 Timeline**：Storyboard 必须基于已分析的真实素材证据，记录素材 ID 和源时间范围；内部 timeline 从已验证的 storyboard 创建，不凭文件名或模型自述猜测媒体内容。
- **产物使用新版本**：Storyboard、timeline、preview 和编辑器交付物不覆盖旧版本；编辑器交付物是从内部 timeline 创建的单向产物，不反向同步。
- **Provider 可替换**：模型连接走统一 Provider 入口。凭据保存在 Windows Credential Manager，不写入 SQLite、浏览器存储或普通日志。失败不静默切换 Provider。
- **失败要可见**：Provider、媒体工具或数据库失败时返回真实且可理解的错误，不用假成功或静默 fallback 掩盖。重试只用于确实能改善的临时问题，且不重复本地副作用。
- **用户确认不可逆操作**：最终导出、覆盖已有导出、删除项目、会话或素材必须先获得明确确认。最终视频导出尚未实现。
- **Preview 是本地检查产物**：Preview 用本地 FFmpeg 生成，用于检查节奏、字幕和画面，不是最终导出，也不修改原始媒体。
- **模型请求按需并发（2026-09-26，取代原「低成本优先」）**：模型请求按需全并发，不为省钱减少调用或限速；只在 429 时按 Retry-After 退避，退避后仍限流就如实失败。

## 三、策划与时长

以下是现行实现。按第一节「素材先行」重做策划时会整体改写。

### 对话媒体选择（2026-09-15，09-27 修订）

输入框下方是「画幅 · BGM · 配音」三项本轮选项，发送后保存快照，同一会话恢复最近已发送的选择，未发送的修改只留在内存。画幅 9:16 / 16:9 / 1:1（默认 9:16），随快照写入分镜，预览与编辑器画布都按它；字幕随配音添加。BGM 开启时由 `generate_storyboard` 直接配乐：先用素材库音频，没有再走 Jamendo，都不可用时如实说明原因。模型不得擅自改动这些选择；明确文字要求优先于开关默认；关闭不删除既有轨道。配音开着就必须配音：已有可念稿照念；只有主题时 Agent 先写稿问同意，同意前不生成。第一版只提供开关，音色、字幕模式和音乐风格不在范围内。

### scriptMode 由系统锁定（2026-09-08）

`scriptMode` 是旁白 / 字幕路径的开关，不交给模型自选。配音关闭时锁为 `key_message`（长 brief 只当剪辑说明）；配音开启且有可念稿时锁为 `full_script` 照念，已被配音锁成 `full_script` 的短 brief 不再打回。响应后再强制钉死，模型只在锁定模式下拆拍。

### key_message 只出字幕标记不配音（2026-09-08）

`key_message` 是短目标 / 提纲成片：Phase 1 默认不写 `onScreenText`（用户明确要求屏幕字除外），`narration` 留空，时间线不自动配音。显式 `synthesize_voiceover` 不得朗读 `onScreenText`，只在拍上仍有 narration 时合成。镜头时长见「没有配音时镜头时长跟画面内容走」。

### 配音开着时口播是时钟（2026-09-17 起）

配音开启时先按已确认 brief 合成旁白再拆拍，合成失败不生成；时间戳优先词级 alignment，没有则句内按字数插值。用户给了成片秒数且与口播相差超过约 30% 时先问用户，并给出按本次实测语速换算的目标稿长；暂停等回答时稿子存为任务 brief，快照写明暂停于哪个工具，下一轮按回答续跑，不得声称未返回的产物。已有配音后禁止改旁白。

### 没有配音时镜头时长跟画面内容走（2026-09-27）

配音关掉时没有口播时钟。用户没说时长时建议 15–45 秒。Phase 4 精修出的源区间决定每镜时长，约 1.5–5 秒（用户要快切 / 长镜时随 `shotLengthHint` 调整），按比例缩放到目标总长，镜头长短自然不同，不再每镜平均。源区间与槽位始终等长（1 倍速）：长了按视觉证据最佳区间裁，短了在锁定窗内向两侧补，锁定窗本身不够长才放慢并在镜头 reason 写明倍速。任何时钟下故事版都不留「源区间长于槽位」。素材库不同素材够每镜一条时不复用；候选确实用尽才复用（仍受 40% 硬上限），并在镜头 reason 写明。简报白天→夜晚：第一个夜拍之前不召回证据为夜景的片段，夜拍不召回白天片段，候选太少时不过滤。

### BGM 开、配音关时音乐定时长（2026-09-27）

有可卡点的曲子时，音乐是时钟：先按目标时长选音乐窗口（乐句起、乐句止，长度偏差不超过 25%），成片总长等于窗口；Phase 4 仍先按精修内容定每镜偏好时长，再把切点吸附到拍上（内容为主、能量为辅，高能量约 1 小节一镜、低能量更长），故事段落切换优先落在乐句边界。曲子没有稳定节拍、太短或分析失败时如实记原因，时长照旧跟内容走。配音开着时旁白仍是时钟，切点只在 ±120ms 内挪到拍上，音乐起点让结尾落在乐句边界。节拍分析在本地完成，不上传音频。Agent 只按 `musicTiming` 说明是否卡点，不凭自己判断声称节拍对齐。

### 源窗短于口播时放慢（2026-09-18）

成片时长跟口播 / 节奏时钟。选中片段的运动可用窗不够长时，保留该画面并放慢播放，不换成更长的片、不冻帧、不补第二镜，也不拼下一段硬切。预览、剪映 / CapCut 草稿和 FCPXML / OTIO 都把整段源区间铺满槽位：槽位长就放慢、短就加快。

## 四、选镜

以下是现行实现。按第一节「素材先行」重做选镜时会整体改写。

### Phase 3 按可见证据选片（2026-09-17）

选片以该拍 `requiredVisual` 与网格画面为准；卡片文字是未核验标签，与画面冲突时看图。旁白只约束时长和口播，不单独决定选哪条。对不上直证时允许诚实的情景承载。网格按该条候选时间窗现拼，缺文件则从源片现抽；无图不作为硬失败。不按题材或画面类型设禁选清单。

### 卡片让位于网格与 CLIP（2026-09-18）

不重跑第一次视觉分析。CLIP 可用时，没有片段图向量的候选不能靠卡片文字抬进前 9。Phase 3 以网格为准。整片候选 Phase 4 锁在 P3 源窗，不再另切窗。

### 召回与选片流程（2026-09-09 起）

- **Phase 1 拆拍**：拆拍前注入素材库视觉 / OCR 库存摘要，`requiredVisual` / `visualKeywords` 贴近库内真实画面，不编造库存没有的主体；brief 叙事意图优先。平均一拍明显长于约 4 秒时软反馈再拆一次，仍粗则收下。
- **Phase 2 召回**：每拍从全库硬切段取 9 条（同片最多 2 段、相似最多 2 条；无硬切则整条一段）。评分含 bge / 词面与 CLIP 图文分：词面去虚词、按词首匹配、多数拍共用的词降权；CLIP 按本拍全库相对换算，模型缺失时为 0；有 CLIP 查询但候选没有片段图向量时，词面 / 语义只当弱提示。后面的拍不因前面池子里没用上的相似段被预删。
- **Phase 3 选片**：各拍同时请求，每拍单独看池内每条候选的网格（弱匹配扩池到 12 条时也全附），每个请求最多 4 张图、网格上下拼接。进入选片前剔除已用、相似和超复用上限的候选；撞车由 Rust 按拍序判定，只打回靠后的镜头并补发该拍。同一拍禁止同片；跨拍允许同一素材不重叠、不相似的片段；已用片段的相似画面硬拒。覆盖一拍允许 1 镜，有第二条不相似且对得上才加到 2–3；主选和替补只在前 5 条。整条选不出镜头则问用户。
- **不等分析**：选片不等待视觉分析，用已打卡的段；段上没卡但素材有旧整片卡时按整条进池，未打卡段不借整片标签。
- **Phase 4 精修**：选中镜头的多帧精修，窗口锁在该片段，不因时长不够拼下一段硬切；每批最多 4 镜、各批并发。
- **落库之后**：故事版落库后同一调用自动预览并新建所选编辑器草稿；能播就不因缺口推迟预览。工作台可列出并打开故事版版本，Agent 改当前打开的那一版，再次生成仍新建。

### 选镜局部编辑走工具，不重跑整条流程（2026-09-25）

`generate_storyboard` 是首次剪辑和改目标的默认流程。生成后对个别镜头不满意，走 `reselect_shots`（指定拍 P2→P5）或 `refine_shot_ranges`（只 P4→P5），其余镜头冻结，不重跑 P1。拍时长以当前时间线为准，配音不动。每次局部编辑写派生 storyboard + 新时间线，同事务提交；P5 校验不可跳过。工具按编辑意图命名，不按 Phase 暴露。

## 五、素材分析

### 技术分析（2026-09-09 起，09-26 调整并发）

- 同时跑本机逻辑核数 1/4（2–8）条素材；每个 FFmpeg 的解码线程按核数平分、合计不超过核数；同一素材的抽帧合并为少量调用且每个输入单线程（8 条且不限线程时 CPU 打满、单条慢 3 倍并超时失败）。
- 段内样本帧与运动曲线同一次顺序解码、按时间选帧（JPEG 固定 q=7）；极短段、超时或数量对不上时再逐帧跳转补抽。
- FFmpeg 低分辨率场景检测找硬切，CLIP 验真后写入真实片段，再在片段内用帧差运动能量收缩可用窗（`analysisVersion=4`）；无已验证硬切则整条一段，曲线对比不够则不收缩。选镜候选单位是片段，Phase 4 窗口用可用区间。

### 画面识别按硬切段整段进行（2026-09-26）

- 每 15 秒一张图、每张 5 帧（最多 4 张 20 帧，超过 60 秒均匀铺开），与技术分析同一批帧，按 960 宽抽。每张是「中间帧大图 960×540 + 其余 4 帧小图」，每帧标编号与源时间（用户定：大图看细节、小图看变化）。一段的全部图同一个请求，各段并发。
- 模型返回：整段共同描述、随时间的变化、每帧主体横向位置（只问大图左右边界，五档由边界换算）、焦点（浅景深与失焦分开）、画面文字 / 品牌标识 / 人群 / 展会、最佳可用区间、高光、竖屏可裁性、开头结尾是否干净、运动方向、光线色调、人数与正脸与防护装备、抽象概念、氛围。水印暂不识别。时间由 Rust 夹回段内，存为 `VisualEvidence.detail`。
- 写模型自拟的叙事功能短语和可见描述并写入片段向量；不把叙事功能收成枚举，不抬 `visualAnalysisVersion`。每个任务最多 6 段。
- 队列最多 16 个任务同时执行（只为限制本机同时编码图片），同一素材的任务不并行。每个模型请求最多 4 张图（Agnes Token Plan 上限），超出由 Rust 本地拒绝。

### 分析失败自动补跑（2026-09-24）

画面识别瞬时失败自动重新入队，每条最多 3 次；技术超时最多 2 次。最后不足 6 段也送审。用户跳过、不适用和 4xx（除 429）不补。不自动换 Provider。

### 全局共享子素材库（2026-09-16）

素材按导入根目录归入全局子库，项目创建时默认选中当时全部已有库，之后新建的库不会被自动加入。关联复用素材 ID 和分析结果，不复制媒体；成员身份不依赖重链路后的路径。旧项目保留自己的素材，主动导入的库自动用于当前项目。浏览、搜索、选片与输出使用同一共享范围；收藏、排除及分析结果随同一素材共享。

## 六、会话与数据

### 每个会话完全独立，包括产物和版本号（2026-09-26）

UI「剪辑会话」就是剪辑任务（editing task），与 conversation 一一对应。故事版、时间线、预览和编辑器交付只属于所在会话；状态快照、`get_edit_status` 和产物面板都只读当前会话。版本号按会话编号，新会话的第一版故事版和时间线都是 v1，局部编辑的派生版本同规则。项目级只共享素材、按内容哈希复用的预览中间缓存，以及选镜时按素材使用次数降权。新鲜度有意保持项目级：同项目多条成片尽量不反复用同一批镜头；它只影响候选排序，不引用其他会话的产物。数据库只追加 `task_version_number` 列，不重建表、不回填：旧版本保留原来的项目内编号，旧会话的新版本从该会话最大号往后接。

## 七、编辑器交付

### 内部时间线是唯一事实，编辑器只接收新交付物（2026-09-18）

内部时间线是唯一剪辑事实。交付前投影为 `HandoffPlan`，由链接器写成目标编辑器格式。只新建、不覆盖、不回读。不把 OTIO 当成产品模型。链接器能力对不上就拒绝或保持未交付，不静默降级。

### 输出端口可选编辑器（2026-09-18）

输出编辑器是项目级选择，记在 `settings_json.outputEditor`。未选择时按本机检测给默认值：CapCut 优先，只检测到剪映时用剪映，都没有时仍为 CapCut；默认值不写回设置。当前可交付：剪映（投放草稿）、CapCut（投放草稿）、FCPXML（Resolve / Final Cut 导入；Premiere Pro 只能导入 FCP 7 XML，不在支持范围）、OTIO（Resolve 导入）。文件导出不弹窗，写到本机 `editor-handoffs`。失败可见，不静默换端口。CapCut / 剪映草稿库都从该设备 `%LOCALAPPDATA%` 注册表识别，不写死盘符。

### 可编辑文字走原生，品牌元素走图片（2026-09-27）

创作者会改的字（字幕、标题、分节字、下三分之一）存为原生文字数据，交付成编辑器里可编辑的文字；做不到的样式如实标 `local_preview_only`，不扩大已验证矩阵。创作者不会改的品牌元素（logo、渐变字、卡片、片尾卡）用 HTML/CSS 模板本地渲染成透明 PNG，交付为图片并明确告诉用户文字不可编辑，绝不伪装成可编辑。

渲染器用应用已依赖的 WebView2，放在独立线程和隐藏窗口里，不打包无头浏览器，也不联网。模型只选模板 id、填短文案，不给时间、样式和位置；Rust 按模板 manifest 截断文案并计算时间。

品牌卡只在项目设了品牌套件时由生成流程自动加，或在用户本轮明确要求时经 `add_title_cards` 加。默认转场是硬切，用户在项目设置里开启，或本轮明确要求时经 `set_transitions` 设置。转场以切点为中心，不改总时长；编辑器表达不了的转场（FCPXML / OTIO 的黑场过渡）保留硬切并在交付说明里写明，不伪造。

## 八、界面

### 界面中英双语（2026-09-25）

一个安装包、应用内切换语言，不分中英两套构建。界面文案集中在 `src/lib/i18n`：中文词典为基准，英文词典按其类型声明，漏键即编译失败；带数量或参数的文案写成函数，英文在函数里处理单复数。语言偏好只是界面便利，存本机浏览器存储；首次启动按系统语言（`zh*` → 中文，其余英文）。界面语言不等于成片语言：配音、字幕与分镜文案跟随用户文案或项目设置。新建项目、会话的默认名称和欢迎语按创建当时的界面语言写入，之后不随切换改名。Rust 面向界面的状态文案给稳定键 `messageKey` 与参数 `messageParams`，由前端按界面语言翻译，中文原文保留作未知键回落与日志；能由已有字段推出的文案直接在前端拼出，不新增字段。发送消息时附带界面语言，只决定 Agent 回复与系统兜底文案的语言。前端默认会话名是 Rust 识别的占位标题，两处必须同步。

### 一体化窗口顶栏（2026-09-15）

系统标题栏改为工作台顶栏内的最小化、最大化 / 还原、关闭按钮，不新增一行；窗口拖动用 Tauri drag region。

## 九、打包与运行时

### 瘦安装包与运行时模型下载（2026-09-19 修订）

默认安装包不捆绑 BGE/CLIP 的 `model.onnx` 大文件。启动缺权重时后台下载到 `%APPDATA%/<app>/runtime-models/`，SHA-256 校验后加载；tokenizer/config 仍随包。下载不阻塞工作台；缺失时 BGE 降级词面、CLIP 加权为 0。先 HuggingFace 官方，再国内镜像 `hf-mirror.com`（同路径同哈希）；单次尝试超时约 20 分钟，中断保留 `.partial` 并自动续传。发行方可用完整包（`npm run models:fetch` 后 `npm run tauri:build:full`）把 ONNX 打进安装包。

本地 BGE/CLIP 推理优先用显卡（2026-09-26）：安装包随带 Microsoft `DirectML.dll` 1.15.4（Windows 自带 1.8 过旧），构建设为延迟加载、运行时按完整路径载入；各模型先建显卡会话并试算，失败回退 CPU，日志写明设备。同一模型推理串行、每次只交一批。

### FFmpeg/FFprobe 随安装包（2026-09-20）

生产安装包捆绑 Gyan `ffmpeg-8.1.2-full_build` 的 `ffmpeg.exe` / `ffprobe.exe`（含 libass，供 preview 字幕）。调用一律走 `process::hidden_command`：优先 `FFMPEG_PATH`/`FFPROBE_PATH`，其次安装包或开发目录资源，最后系统 PATH。二进制 gitignored，构建前 `npm run ffmpeg:fetch` 或 `npm run tauri:build` 自动拉取。

### Tesseract 随安装包（2026-09-23）

生产安装包捆绑 UB Mannheim Tesseract 5.4.0 Windows 运行时与英文 `eng.traineddata`。构建脚本固定安装器与 7-Zip 解包器版本并校验 SHA-256，只解包到 `src-tauri/resources/tesseract`，不安装系统程序；二进制 gitignored。运行时解析顺序为 `TESSERACT_PATH` → 安装包 / 开发目录资源 → `Program Files` → PATH。`get_release_readiness` 通过 `--list-langs` 确认 `eng` 可用，缺失时阻止显示 ready。

### Python/剪映草稿 SDK 随安装包（2026-09-20）

生产安装包捆绑官方 Windows embeddable CPython 3.12.10，并预装 `pyJianYingDraft==0.3.0`、`pycapcut==0.0.3` 与 `MediaInfo.dll`。`python_program()` 优先 `PYTHON_PATH` 与随包 `python.exe`，未拉取时 Windows 回退 `py`，且不得把 `py -3` 传给 embeddable 解释器。启动适配器时把随包 FFmpeg/Python 目录插到子进程 PATH 前面。运行时 gitignored，构建前 `npm run python:fetch` 或 `npm run tauri:build` 自动拉取。

Tauri CLI 多次 `--config` 会覆盖 `bundle.resources`，不会拼接数组。`scripts/run-tauri.mjs` 在构建时把基础资源与 FFmpeg/Python（及可选完整 ONNX）清单写成一份 `src-tauri/target/tauri.merged-resources.conf.json` 再交给 CLI。Python 树用目录路径拷贝，不用 glob。

## 十、协作

### 默认直推 master，并行时主会话管验收（2026-09-16，09-28 补充）

单个会话默认在 `master` 提交并推送，不为每个改动建分支、开 PR，也不在每次提交前跑完整 `harness:test` / `cargo test` / `npm run build`。提交钩子只拒绝 detached HEAD，并检查文档同步。多任务并行时由主会话定方向、写任务书、按证据验收，代码交给各自开独立 worktree 的执行会话；细则见 `CONTRIBUTING.md`「主会话与执行会话」。
